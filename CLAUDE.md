# CLAUDE.md — XMen2Recomp

Publication tier: public (public since 2026-10-24: nothing personal in files, messages or history).

Static recompilation of **X-Men 2: Clone Wars** (Sega Genesis, USA/Europe, SHA-1
`61409e6cf6065ab67d8952b891d8edcf47777193`) to native C with
[segagenesisrecomp](https://github.com/mstan/segagenesisrecomp). Phases 2 (recomp, complete) and 4
(hand-written C) of the xmen2disasm roadmap live here: criteria in
`xmen2disasm/docs/phases/P2-recomp.md` / `P4-decomp.md`, checked from the disassembly repo with
`uv run tools/phase.py 2|4`. Findings and open questions go in [docs/NOTES.md](docs/NOTES.md)
(phase 4: section "Phase 4").

## Layout

| Path | What |
|---|---|
| `segagenesisrecomp/` | Engine submodule = fork `crabsmack/segagenesisrecomp` (branch `master`). Its `external/m68k-recomp-core` (the recompiler core) points at fork `crabsmack/m68k-recomp-core`, branch `xmen2`. |
| `xmen2disasm/` | Pinned disassembly submodule (`crabsmack/xmen2disasm`): ground truth for discovery. |
| `game/game.toml` | Recompiler config. `xmen2.*` next to it are generated by `tools/sync_disasm.py` and committed. |
| `game/xmen2_spec.c` | GameSpec: entry/IRQ dispatch, per-frame CRC trace, state dumps, K7 counters. |
| `game/xmen2.bin` | The ROM. Gitignored, **never commit it**; `tools/common.py` copies it from `$XMEN2_ROM` or `../xmen2disasm/xmen2.bin`. |
| `tools/xmen2check.py` | The phase-2 contract (`gen`, `build`, `trace`); must report only what the tools did. |
| `tools/compare.py`, `tools/diffstate.py` | First-divergence helpers (trace vs reference CSV; state dump diff with RAM global names). |
| `build/` | CMake tree (Visual Studio 2022, x64). Generated C lands in `build/generated/xmen2/`. |

## Rules

- **Nothing personally identifying goes into this repo, history included** (the user's ruling
  for the public release): no names in files or messages (write "the user"), no local paths,
  machine details or the user's other projects, no `Claude-Session:` commit trailers, author
  `crabsmack`, commit times in UTC (`.claude/settings.json` sets `TZ=UTC`; outside Claude,
  `TZ=UTC git commit`). Notes about this machine go in an untracked `CLAUDE.local.md`. Video
  production (editing, the release cut) lives outside the repo; `tools/capture.py` and
  `platform/native/capture.cpp` are the port's own recording.
- **The ROM never enters git** (`git log --all` must never show a `.bin/.gen/.smd`; K1 checks).
- **Never edit generated C** (engine PRINCIPLES #19). Fix the recompiler (core fork), the
  engine (engine fork), `game.toml` or the spec, and regenerate.
- **Discovery comes from the disassembly** (#16): change it in xmen2disasm, bump the
  submodule, `uv run tools/sync_disasm.py`. Never seed from `dispatch_misses.toml` alone.
- **Commit order** (#20): m68k-recomp-core fork -> engine fork (submodule pointer) -> this
  repo (submodule pointer). Never push a pointer to a commit that isn't pushed. Other projects
  push to the engine fork's master too: when it has moved past the commit tested here, merge on
  the fork's master and keep this repo's pin on the tested commit (reachable from master); run
  phase.py's smoke stage before pinning a moved master. New exact-mode statics belong in
  exact_sched.c's `k_exact_rb` (`GENESIS_RB_PROBE=997:64` over the TAS catches a missing one).
- **Git in worktrees.** Never `git submodule deinit` in a linked worktree: it edits the shared
  `.git/config` and unregisters the main checkout's submodules too (repair: `git submodule init`
  there). A worktree whose submodules were initialized needs `git worktree remove --force`. A
  0-byte `index.lock` (in `.git/`, `.git/worktrees/<name>/` or `.git/modules/<sub>/`) seconds old
  is a live status poll: wait. An old one with no `git.exe` running is stale: delete it.
- `tier3_floor_default` stays 0: a dispatch miss must be loud (K7 needs 0 misses, 0
  interpreter instructions).
- One runner at a time (#24); kill a stuck one **by PID**, never by image name. (A phase-2
  rule. Phase 4's retrospective recommends retiring it once workers get their own build dir and
  runner copy, so they can verify per batch. That is the user's call at phase 5 P0: see
  `xmen2disasm/docs/LESSONS.md`, which also lists this repo's open speed-ups, such as
  runner-native savestates for fuzz runs. Headless traces, verify and `tools/gate.py` play
  private runner copies and run side by side.)
- No CI (the ROM can't be in it): the gate is `uv run tools/phase.py 2` in xmen2disasm.
  Commit and push after every green batch (trunk-based, `main`).

## Commands

```
uv sync                                   # cmake for the build
uv run tools/sync_disasm.py               # regenerate game/xmen2.* from the pinned disassembly
uv run tools/xmen2check.py gen            # regenerate into build/gen-check, count problems
uv run tools/xmen2check.py build          # Release runner -> build/Release/XMen2Recomp.exe
# trace: input from xmen2disasm `uv run emu/export_input.py tas --out X.input`
uv run tools/xmen2check.py trace --run tas --input X.input --out build/trace-dev/tas --frames 600 [--dump-frames 4,5]
uv run tools/compare.py build/trace-dev/tas/frames.csv --ref tas
# reference state at frame N: in xmen2disasm, uv run emu/dump_state.py tas --frames 4,5 --out DIR
uv run tools/diffstate.py build/trace-dev/tas/dump DIR --frame 4
```

The runner is played headless with `--benchmark N --input-script FILE` (hidden window,
uncapped); `XMEN2_TRACE_CSV` makes the spec write the per-frame CRCs.

## Phase 4 (hand-written C)

| Path | What |
|---|---|
| `game/c/<ADDR>.c` | one hand-written function per file (C89 for MPW C 3.3, built as C++17 on PC) |
| `game/include/` | `xmen2.h` = mem (mode switch) + types + macros + globals + data + funcs |
| `game/runtime/` | `handc_rt.cpp` (C<->68000 calls), `verify.cpp` (shadow tests) |
| `build/bridge*` | generated by `tools/bridge.py` (wrappers, stubs, slot entries) |

Runners: `XMen2Recomp` (timed, all generated), `XMen2Stepped` (untimed, replay by logical
position, C where it exists), `XMen2Verify` (timed + C as shadow tests). With no
`GENESIS_REPLAY_IN`, `build\Release\XMen2Stepped.exe game\xmen2.bin` runs frame-synchronous with
all hand C and live input: the D8 playtest build (only the user writes `handc-verified:` in
`docs/USER_VERIFIED.md`). In exact mode (the timed and verification runners), C that calls 68000
code and wants control back at its RTS wraps the call in `XCALL_BEGIN(XAWAIT_ANY)` /
`XCALL_END()` (handc_rt.cpp CALL_FROM_C, verify.cpp run_gen); otherwise an RTS that returns
further out runs the game on from there.
```
uv run tools/xmen2check.py build                          # all five runners (+ bridge, export table)
uv run tools/xmen2check.py trace --run tas --input X --out D --sync         # D1: + sync.csv, replay.bin
uv run tools/xmen2check.py trace --mode stepped --run tas --replay D --out E  # D2
uv run tools/xmen2check.py verify --inputs DIR [--functions A,B] [--frames N]
uv run tools/xmen2check.py types|handc|lint
uv run tools/pccheck.py game/c/X.c      # compile one file as C++ (no build tree; safe in parallel)
#   PC mode only: `#if defined(XMEN2_NATIVE)` branches aren't compiled; `xmen2check.py build` is their check
# matching: in xmen2disasm, uv run tools/cc.py --match PATH/TO/XMen2Recomp/game/c/X.c
uv run tools/replaydump.py D/replay.bin --sync N; uv run tools/syncdiff.py A.ram B.ram
```

## Phase 5 (native port)

`XMen2Native` (built by `build` with the others; `platform/native/native.cmake`) is the port: the
hand C in `xmen2_mem.h`'s NATIVE mode with **no 68000 at all** — game memory in the native arena
in host byte order (`game/runtime/native_rt.cpp`), calls through stored pointers direct
(`bridge.py --mode native`), the hardware behind `platform/xmen2_platform.h` (its own machine:
`platform/native/machine.cpp`; the recomp runners use `platform/plat_engine.cpp`), the host side in
`platform/native/main.cpp` + `host_sdl.cpp` (SDL2 window, pads, sound). Its sync rows are the CRCs
of the exported 68000 image (`game/runtime/export.cpp`). With no `--benchmark` it is played:
`build\Release\XMen2Native.exe game\xmen2.bin`. Notes: docs/NOTES.md "Phase 5". platform/native and
game/runtime are one link: a file-local type goes in an anonymous namespace (two namespace-scope
`struct Mark`s once shared one `std::vector` reallocation and corrupted a vector).
```
uv run tools/xmen2check.py package [--platform linux] --json   # P8/P9: the ROM-free zip, scanned (tools/romscan.py) and smoke-tested
uv run tools/xmen2check.py native-build --json                 # XMen2Native alone (CMake XMEN2_NATIVE_ONLY): the Linux build
uv run tools/xmen2check.py native-build --wsl --json           # that build in WSL (~/xmen2-native-build/<tree hash>), as P9 and Linux seats use it
#   native-build configures its build dir for XMen2Native alone: a later full `build` or gate.py in the same
#   dir fails (MSB1009, no XMen2Recomp.vcxproj). Give the gate its own: XMEN2_BUILD=build-full.
#   Runs by hand: one runner exe per process. 14 processes of one exe from one folder at once gave 2 of 46
#   runs where nobody was ever in play (both old and new runners, fine alone): copy the exe per run, as the harness does.
```
```
uv run tools/xmen2check.py build --native --json   # + per object: what it still needs from the 68000 (COFF), and the link map
uv run tools/xmen2check.py trace --mode native --run R --input F --replay REFDIR --out D --json [--fb]   # + "exported"
#   --fb (any stepped mode): + sync.csv column fb_fnv1a64, the frame rendered at the previous sync point
uv run tools/synccorpus.py --refs PHASE_TRACES --mode stepped-gen --fb --out REF --jobs 24   # references, this engine
uv run tools/synccorpus.py --refs PHASE_TRACES --mode native --fb --against REF --out D --jobs 24   # all runs vs them
XMEN2_EXPORT_SELFTEST=1 (or a global's name)   # negative test: one byte of the image zeroed
XMEN2_FIBER_ANYWHERE=1   # XMen2Native: the game's fiber stack where the OS puts it, not XM_FIBER_BASE
#   the check for stale-stack reads, which the fixed place makes repeatable (NOTES "scene42"): two runs
#   of a case must give equal game rows. No state-file loads with it set.
```

Harness (NOTES.md "Phase 5 harness"). `XMEN2_REFS` = the phase-4 `build/phase_traces` (inputs and
D1 REFDIRs; harness.py's default is `$XMEN2_DISASM/build/phase_traces`, `XMEN2_DISASM` defaulting
to the xmen2disasm checkout next to this one; CLAUDE.local.md has this machine's paths). A fresh
worktree here: `git submodule update --init --recursive segagenesisrecomp` only (recursing into
xmen2disasm fetches emu/gpgx from GitHub and fails offline; nothing here needs it), and
`XMEN2_ROM` set to the ROM; its first gate run builds everything (~5 min). The
runners are reproducible (CMakeLists `XMEN2_REPRODUCIBLE`, /Brepro): same sources, same SHA-1, so
stepped-gen reference rows are cached by runner hash in `.git/xmen2-cache` (all worktrees).
phase.py runs from the main xmen2disasm checkout (its `build/phase_traces` holds the references and
caches; a fresh disasm worktree has none) with `XMEN2_RECOMP` = this worktree and `XMEN2_DISASM` /
`XMEN2_REFS` set (else P9 looks for the corpus beside the worktree); stage lines go to
`build/phaseN.log`. Its jobs follow the threads (cores less two; `PHASE_JOBS` overrides) and each
pool waits while free RAM is under 3 GB (`PHASE_MIN_FREE_GB`), so don't lower `PHASE_JOBS` for memory.
```
uv run tools/gate.py [--files game/c/A.c ...] [--mode native]   # worker batch gate, own build dir: build,
    # pccheck, MPW match (docs/p4_mpw_matched.txt), verify + 6,000-frame TAS trace; fail-fast, one line per step
uv run tools/bench.py [--quick]          # the P0 gates -> docs/bench.json (clean build, corpus check, 2 build dirs)
uv run tools/pccheck.py --all            # all game/c on 32 threads (~80 s; one file ~1 s)
xmen2check.py verify ... [--keep-going]  # fails (exit 1, names the run) when a run's testing stopped early
xmen2check.py trace ... [--keep-runner]  # a passed trace deletes OUT/runner (XMEN2_KEEP_RUNNER=1 keeps it)
xmen2check.py trace ... [--render]       # stepped/native traces comparing no picture skip the render; --render keeps it (control)
uv run tools/xmen2check.py trace-group --runs RUNS.json [--fb|--options ...|--state-probe P:L]   # many native traces
#   verify and trace-group play each run that branches from the TAS as its own process from a TAS state file
#   (runners' --state-at/--state-load); --in-process / --no-branch are the controls. Only the harness's runner
#   copies (fixed base, one XMEN2_GS_COOKIE per group) can load a state; a runner started by hand can't.
#   A group with pictures also splits every run over --segment-frames (4000; 0 = the control): a --no-pixels
#   producer saves the states, segments play from them, the harness joins the files (NOTES "Split runs").
uv run tools/statecheck.py               # cross-process state loads + negative control (~40 min)
uv run tools/soundcheck.py [--only boot,18] [--players 4,3] [--seeds 1,40,78]   # music_voices: each part song's
#   notes on the music machines vs a reference, note for note, and full's parts as a superset of them; XMEN2_KEYON_LOG=FILE logs the notes
```
`music_voices` (default `full`; `1` the game's thinned parts, `0` the cartridge) is sound only: sound2.cpp's
music, parts and full-parts machines, not in the digest (the second machine, players 3-4's, is in it and
plays silent under `full`). The
counters line's `"sound"` (per machine and song: key-ons, stolen voices, sounding ms) is the measure
for sound work. `tools/capture.py render` on a take without a `runner frames:` header runs unbounded:
pass `--frames N`. phase.py 7 runs phase 6, which runs phase 5: run only the highest phase you need.

## Phases 6-7 (options, online play, four players)

Criteria: xmen2disasm `docs/phases/P6-enhance.md`, `P7-multiplayer.md`; notes: docs/NOTES.md
"Phase 6", "Phase 7". Every difference from the original is an option of `XMen2Native`, off by
default, except presentation-only ones whose default the user sets: `music_voices` (sound) on,
`high_fps` and `widescreen` `auto` (the display's; no window, so every headless run and check:
off). `platform/native/options.cpp` (the table,
`--options K=V,...`, `xmen2.ini [options]` beside the exe), read by the game's `#if
defined(XMEN2_NATIVE)` branches through `g_opt` (`platform/xmen2_options.h`). A new option goes in
both files, in README.md's table and in the package README (`PACKAGE_README` in xmen2check.py).
Savestates: `platform/native/state.cpp` (sections registered at start; M2's negative control
leaves each out and must catch it).
Players 3-4: `platform/native/players.cpp` (their pads, VRAM, HUD and the `mp` counters). Netplay:
`platform/native/netplay.cpp` on the engine's recomp-net and rbengine; the host's game options are
sealed into the session, presentation ones (`high_fps`, `music_voices`, the 16:9 view unless
`widescreen_gameplay=1`) stay each seat's. **A release whose game differs from the last one bumps
`NP_VERSION`** (netplay.cpp), so mismatched seats refuse each other instead of desyncing. M6 needs
the user's `multiplayer-verified:` line in `docs/USER_VERIFIED.md`.
```
uv run tools/xmen2check.py options --json          # E2: the options as the runner lists them, and xmen2.ini read
uv run tools/xmen2check.py netplay --seats N --input F --out D [--options K=V,..] [--transport lan|hub|ice]
#   [--link latency=L,jitter=J,loss=P,seed=S] [--seat-options I:K=V,..] [--linux-seats ..] [--scene S --session N]
#   N seats of the release runner on loopback (or Windows + WSL), seat i playing column i+1 of F; each writes
#   D/seat<i>/sync.csv, digest.csv (its final timeline) and seat.json
XMen2Native.exe --netplay --json                   # the transports this build has
```
